# 正式课表与教务登录

应用直接读取本科 BYXT 或研究生 GSMIS 的正式课表，并在加载后单独关联 iClass 签到场次。

## 数据解析与认证

`AcademicTimetableProtocol.kt` 将本科接口返回的日期、周次和节次转换成应用的课表数据。`GraduateTimetableParser.kt` 使用研究生接口的教学班、周掩码、首次上课日期和节次方案生成周课表。未知星期显示在未安排列表，未知时刻显示待定。

`AcademicAccessProtocol.kt` 和 `IclassRepository.kt` 通过 OkHttp 管理教务认证和数据源选择。

1. CAS 提交后激活 UC，再用 `/api/uc/status` 验证登录。
2. 直接访问 HTTPS BYXT `.../home/currentUser.do`，绕过根首页的 HTTP 跳转及脚本导航。
3. 探测本科门户后实际读取本科学期、周次及周课表；成功才采用本科数据。
4. 本科不可用时验证 GSMIS 真实课表；成功后在本次会话缓存研究生路由。网络失败本身不证明学生身份。
5. 直连／WebVPN 共用各自会话 Cookie。只升级默认端口 HTTP CAS 跳转，校外请求保持网关路由，不允许任意不可信地址或转发密码到业务主机。

本科接口：GET `schoolCalendars.do`、GET `getTermWeeks.do?termCode=...`、POST `getMyScheduleDetail.do`，表单为 `termCode/type=week/week`。研究生沿用 GSMIS 我的课表入口、学期列表与 `loadXskbData.do`；表单为 `ZC/XNXQDM/XH/XQDM`。

## 界面与签到

登录页恢复 v2.1.0 蓝白水彩样式，网络模式在表单顶部可见；没有学生身份选择、右上角模式菜单或学期日期控件。记住密码、自动登录独立选择；启动自动登录只尝试一次，退出会关闭自动登录。

课表按学校周次与真实节次显示；2026 秋季默认基准日为 2026-09-07。正式课表先发布到界面，再单独关联 iClass。编号／教学班号、规范化名称、日期及起止时刻必须唯一对应，真实排课 ID 在全周不得跨记录复用。无匹配、时间未知、刷新失败的课程禁用签到，不使用教务编号代替签到排课 ID。

课表读取失败时会显示错误。用户可点右上角「切换」打开独立的 iClass 签到列表，再点一次返回课表签到。课表模式从课程详情提交签到，iClass 模式也可直接从列表提交。签到均由用户逐场主动点击，自动登录、加载和刷新不会提交签到。

自动测试使用构造的接口响应和演示数据。学校实际接口行为还需用真实账号和手机验证。

## v2.2.9 分场次签到

课表仍展示正式课程完整时段，允许同日、同课程编号/教学班号且规范化名称一致的多条 iClass 排课落在该时段内。子场次必须起止时间有效、彼此不重叠、各自只对应一门正式课程，真实ID不能被其他记录复用。允许分场之间有课间休息，不要求每个子场次起止时间等于整门课程。

每个已识别场次在详情中独立按钮、独立状态；课程卡片显示“已签1/2”，全部场次完成才标已签到。每次仅提交选中的实际场次，禁止将合并课程直接作为批量签到。相同时间的多教师排课保留每个真实ID的结果，部分成功后重试会跳过已成功ID。同周刷新保留已知成功状态，退出后清理会话。

未知日期/时间、跨日、超出正式课程时段、身份不符、重叠或ID冲突的排课不会自动启用。这里只显示成功关联的场次；学校未返回或存在歧义的记录需要继续核对，不宣称已识别所有签到场次。自动测试使用模拟数据，未以真实账号提交签到。

## v2.2.9 无需签到状态

成功查询本周全部七天的iClass排课后，若某门正式课程没有同编号/教学班号或同名称的记录，且当日不存在同时间身份不明的排课，则显示“✓ 无需签到”。该状态独立于已签到，不向服务器提交、不计为实际签到。仅在最终关联阶段判断，正式课表刚加载时不会提前显示。

查询失败/超时、仅取得部分日期、存在相关但时间/身份不符记录或ID冲突时仍待确认，不显示免签勾号。之后学校新增排课时，刷新会重新判断并恢复实际签到场次。该判断表示当前查询中无iClass排课，不代表学校对未来排课或出勤要求的永久判定。

## v2.2.9 显示与统计修复

详情隐藏教学班号和iClass排课ID，保留内部关联数据；删除“来自所选学期的正式课表”小字。提示改为“请根据实际出勤情况操作，结果以智慧北航APP‘智慧教室’为准。”

周课表宽度按可用屏幕均分七天，无最小364dp宽度限制，不需要横向滑动才能看到周日。学期名称和加载状态独占一行区域居中，可换行，边缘保留内距。

顶部统计独立于课表课程数：按需要用户点击签到的独立场次统计总数与完成数；同一时段多教师的后台排课ID合并为一次操作，分开的时段分别计算。同场后台部分成功会保留结果供重试，但该场全部完成才计一次已签到。没有排课的免签课程、尚未取得有效关联的课程不加入已确认总数。教务课表课程数量仍保留为内部独立字段，不再作为签到分母。正在关联时显示加载提示，失败仍显示原有警告，避免把未取得的记录当成已确认无签到。

## v2.2.9 场次统计与文案

“结果以智慧北航APP‘智慧教室’为准”独立换行。统计与详情页的签到按钮保持一致：一次对外签到场次计一次，不按老师或后台排课ID数量重复计数；例如两个时段各有两位老师，总数为2，前一时段完成后为1/2。无需签到课程仍不计入分母。

## v2.2.9 完成标识

多场次课程全部完成后，课表卡片与详情统一显示“✓ 已签 2/2”；未完成仍显示“已签 1/2”。签到场次统计与实际提交逻辑保持不变。

## v2.2.9 勾号统一

已签满的多场次课程、普通已签到课程和无需签到课程统一使用✓。课表中的完成勾号统一使用11sp独立显示；多场次计数另用9sp显示，避免把勾号随计数缩小。详情中的满签进度显示“✓ 已签2/2”。

## v2.2.9 统一认证图片验证码

应用从认证页面识别验证码要求，用同一临时 Cookie 会话请求 CAS 图片，并随原表单字段提交用户输入。

登录页按需显示验证码图片与输入框，点击图片或刷新按钮重新取认证页和图片，旧输入清空；输入错误导致返回验证码页时停下来显示新图片。自动登录只尝试一次，遇到验证码等待手动输入。切换账户或网络、退出、关闭均使旧验证码会话失效。验证码及execution不写入保存凭据，不显示到运行日志。

图片始终请求固定的受信CAS端点，VPN模式保持在WebVPN网关；校验图片类型、大小和显示尺寸，不访问任意图片地址。只显示并提交用户手动输入，不进行验证码识别或绕过。

测试使用构造CAS响应和演示图，未使用真实账号；上线前仍需校园直连/校外网络的实际验证。

验证码检测使用 HTML 和 JSON 解析。自动测试覆盖配置识别、登录字段、图片获取与手动重试。
