# Kotlin + Compose 原生版

登录页恢复 v2.1.0 风格，可选自动登录。应用根据认证与课表响应识别教务数据源，按学校的周次和节次展示正式课表，再关联签到。

支持一门课程的多个独立签到场次，逐ID保留部分成功状态。确认iClass本周完全没有相关排课的课程显示✓无需签到；请求失败或存在匹配冲突时仍待确认。

## 历史：v2.0.1 直连兼容修复

用户后续确认 v2.0.0 真机 VPN 登录可用，但校园 Wi-Fi 下直连登录出现“不可信的地址”拦截。公开认证入口的无账号 GET 检查返回正常表单；尚未取得手机上实际被拦截的目标，不能断言具体是哪一个门户地址。

直连认证提交后可能跳到与课程登录无关的通用门户。现在仅在直连 CAS 提交链的 302/303 离开认证页时停止跟随该地址，继续使用固定的 MyCenter 与课程登录接口确认会话；不会请求或将该门户加入白名单。307/308 仍限制密码发送目标，首次认证页、课表及签到请求也维持原有检查。VPN 保留跳转流程以完成其会话交换。

日志增加“已获取统一认证页面，正在提交认证”和“认证提交完成，正在连接课程服务”，仅在课程接口确认完整用户及会话后记录登录成功。仍被拒绝的地址只显示主机、协议、端口，不显示路径、查询参数、票据或账号密码。

新增回归覆盖门户跳转、同认证域中转、密码错误、课程认证失败、307/308 密码保护和诊断脱敏；保留 VPN 完整流程回归。用户后续已确认 v2.0.1 的校园直连和 VPN 登录可用。

本次构建、APK 签名核验与 59 项测试全部通过（协议 7、模拟网络 15、界面状态 16、凭据加密 4、交互 14、渲染 3），无失败及跳过。Lint 0 错误、16 警告。签名仍与 v2.0.0 相同。

## 历史：v2.0.2 研究生教务课表对照

针对 iClass 中仍保留已退课程的情况，新增研究生管理系统（GSMIS）课表读取。每次加载或刷新周课表时，使用当前登录会话访问 GSMIS 的课表入口、学期列表与所选学期课程清单；校外模式通过 WebVPN 访问。学期依据学校返回的名称与学期基准日匹配，不能确定时由用户选择，不根据不透明学期代码猜测。

对照使用 iClass 课程号与 GSMIS 课程编号或教学班号，加规范化后的课程名称。至少找到一条准确对应后，才过滤编号和名称均不在正式课表中的排课；字段缺失、只匹配编号或只匹配名称的排课仍显示为待核对。对应关系为空、无可靠匹配、页面返回 HTML 或请求失败时，保留 iClass 原始课程并暂停整周签到。学期切换会清除旧对照结果后重新读取。

整周签到仅提交对照确认的排课 ID，待核对记录不参与；单门课程仍可由用户确认后操作。界面可以查看所选教务学期、已过滤的排课及读取失败的原因。若 iClass 用相同课程号和名称表示不同教学班，现有字段可能无法区分换班前后的记录，因此该功能不保证识别所有退课情况。

测试覆盖学期选择、字段异常、部分数据、空课表、课程号对应关系、残留课程过滤、冲突排课 ID、直连与 VPN 的会话流程，以及整周签到和界面状态。测试使用构造数据和模拟网络；公开 GSMIS 入口在本机返回“请在校园网环境下访问”，尚未使用真实账号验证新版教务接入。

HTTP 路径和字段参考公开项目的协议实现后独立编写 Kotlin 代码。来源、字段映射、保留策略与实际验证范围见 [GSMIS 接入说明](GSMIS_INTEGRATION.md)。

## 安全与兼容

- 所有 HTTPS 请求正常校验证书及主机名，认证表单和跳转限制在学校可信地址。
- 学校当前直连签到接口仍为 HTTP，只对 `iclass.buaa.edu.cn` 开放明文；客户端仅允许既定 8081 端口签到路径。校外模式通过 HTTPS WebVPN 访问。
- 不持久化登录 Cookie、会话 ID 或未勾选记住的密码，不将密码写入 Activity 保存状态和日志。
- 自动登录与学生身份仅随已成功验证的凭据加密保存；自动登录不会触发签到，退出后不会重新自动进入。
- 沿用原包名及本机签名时，可覆盖安装；兼容读取此前保存的凭据。请勿卸载旧版来完成升级，否则系统会删除其数据和密钥。
- 功能迁移不改变既有代码及素材的权利归属。
